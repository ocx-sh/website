## tabs-scrollbars

- Root cause: `.ocx-tabs > [data-part='list']` set `overflow-x: auto` with no
  `overflow-y`. Per the CSS Overflow spec, `overflow-x: auto` alone computes
  `overflow-y: auto` too — so any sub-pixel vertical overflow (line-height
  rounding, the trigger's focus-ring/border tricks) drew a vertical scrollbar
  the list must never have. Confirmed by reading `Tabs.astro` and
  `tab-icons.mjs`/`starlight.css` — the "Starlight tabs / code-group path" is
  entirely this project's own `<Tabs>` (Starlight-compatible override), no
  separate native Starlight tabs component exists to check.
- Fix (`packages/theme/src/components/Tabs.astro`): pin `overflow-y: hidden`
  next to `overflow-x: auto`, add `scroll-snap-type: x proximity` on the list
  and `scroll-snap-align: start` on each trigger (native focus-scroll already
  brings the active tab into view on keyboard nav; scroll-snap makes horizontal
  scroll and the click case feel intentional too — no JS added).
- Scrollbars site-wide (`packages/theme/src/base.css`, new `/* scrollbars */`
  region at the end of `@layer ocx`): `scrollbar-color`/`scrollbar-width: thin`
  on `:root` (inherited, covers everything); `::-webkit-scrollbar{,-track,-thumb,
  -thumb:hover}` fallback rules on the shapes that actually overflow (`html`,
  `pre`, `.expressive-code pre`, `.ocx-table-scroll`, the tabs list, `dialog`,
  `[role=dialog/listbox/menu]`, `.sl-sidebar`). Hover darkens the thumb using
  `--ocx-color-border-control` (neutral), never accent. `scrollbar-gutter` left
  untouched (no shift observed from this change).
- Tokens (`packages/theme/src/tokens.css`): `--ocx-color-scrollbar-{thumb,
  thumb-hover,track}` in both the light and dark blocks (thumb = border-strong,
  hover = border-control, track = transparent), plus a `--ocx-scrollbar-size:
  10px` geometry token. Also restored `--ocx-color-hover-border`'s **dark**
  declaration — it was light-only already, before I touched the file (another
  agent's concurrent edit), which fails `dark-parity.mjs`; one-line fix, no
  functional change to that token's light behavior.
- Docs: added a "More tabs than fit" state to
  `examples/starlight/src/content/docs/components/tabs.mdx` (12 labelled tabs,
  documents the horizontal-scroll behavior).
- Test: new e2e in `tests/e2e/zag-tabs.spec.ts` — asserts
  `scrollHeight <= clientHeight` on the overflowing group's tab list at both
