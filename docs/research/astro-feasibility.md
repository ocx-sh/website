## Shared components across repos

For: Starlight `components` overrides (Header, Footer, PageFrame) + plugin API are the sanctioned distribution path. Precedent: nebari-dev/starlight ships one shared Starlight theme package to several docs repos (EffVer, consumers pinned to a macro line); onury/docs-kit uses moving major tags. Astro Container API renders `.astro` in Vitest without a dev server. `base` rewrites assets and autogenerated sidebar links.
Against: Container API still experimental (breaking in minor/patch). `base` does not prefix root-relative links inside Markdown content (community `starlight-base-path` plugin patches it). Theme preference key `starlight-theme` in localStorage is per-origin — shared across all sections on one domain (collision noted for multi-instance; for one brand this is arguably desired). Subpath 404 collision bug #1080. Multi-instance-per-domain is an open discussion (#956), not a supported feature.

## Python SDK API reference

For: `starlight-pydocs` (Phil Ewels) uses Griffe (same engine as mkdocstrings-python): cross-referenced signatures, Google/NumPy/Sphinx styles, inherited members, objects.inv, llms.txt, per-module pages, `<Autodoc>` embed; can run from a pre-dumped Griffe JSON (no Python on the docs host). Fallback: `griffe2md` (mkdocstrings org) → Markdown pre-build step.
Against: starlight-pydocs has ~7 stars and a fork; decoupled Python-docstrings→JS-SSG is an emerging pattern; no production Python SDK found on it.

## Lighthouse

For: zero-JS-by-default islands; comparisons favour Astro/Starlight over VitePress on LCP/JS payload (VitePress ships a Vue SPA runtime, ~100–200 KB).
Against: Starlight a11y audit #2693 found contrast/reduced-motion issues (own tokens would replace colours anyway); unused-JS deduction applies to any un-split island (search, theme toggle). No citable published 100/100/100/100 run of a Starlight site with Pagefind.

## Pagefind mergeIndex in Starlight

For: Pagefind multisite supports `mergeIndex` (UI config or `pagefind.mergeIndex(bundlePath, {indexWeight, mergeFilter})`); same-origin needs no CORS; Starlight `Search` override can host a custom PagefindUI.
Correction (verified against Starlight `docs/.../reference/configuration.mdx` on main, 2026-09-27): Starlight's `pagefind` option now exposes `mergeIndex: [{bundlePath, indexWeight, basePath, baseUrl, mergeFilter, language, ranking}]` — no Search override needed; discussion #1358 is outdated. `basePath`/`baseUrl` rewrite result URLs per section. Merged bundles load lazily on search open.
Against: Pagefind maintainer (#564): query-time merge only "vaguely efficient"; for 10+ sites prefer one physical index built from combined output.
