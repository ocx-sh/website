`ConfirmDialog` and `AlertDialog` are the base [Dialog](../dialog/) with the action row and the
wiring already done. Neither renders a trigger: place one once, anywhere, and pop it from any
script with `ocx:dialog:open` (`{ id }`), the same pattern `ocx:toast` uses. The outcome comes back
as `ocx:dialog-result` (`{ id, value }`), bubbling from the dialog's own root.

## Events

- `ocx:dialog:open` `{ id }`: dispatch on `document` to open the preset whose id matches; it has no other way in.
- `ocx:dialog-result` `{ id, value }`: exactly once per close. `value` names the button that closed
  it (`'confirm'`, `'cancel'` or `'ok'`), or is `'dismiss'` for Esc, the X button or an outside
  click. A caller waiting on the outcome always hears back; treat anything but `'confirm'` as no.
- `ocx:dialog:change` `{ open }`: the dialog opens or closes, as the base Dialog.

## Keyboard

| Key | Action |
|---|---|
| Enter, Space | On an action button: run it; the dialog closes and reports it. |
| Tab, Shift+Tab | Move focus within the dialog; it wraps at the ends. |
| Escape | Close the dialog (`value: 'dismiss'`); focus returns to where it was before it opened. |
