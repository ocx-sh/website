Fences alternate by position: the first, third and so on are commands, the second, fourth and so on are outputs.
A command with no output goes in the same fence as the next command.
Every command line starts with an accent `$`, every output line with a `>` in the comment colour, whatever the output's language.
The markers are drawn, not text: neither selected nor copied. A line after a trailing `\` continues the command: it keeps its indent and gets no `$`; neither does a blank line or a `#` comment line.
A command has a copy button, which copies only the command; an output has none.
With `play` the session types itself once it scrolls into view; keep lines short enough not to scroll sideways. With `collapsed` every output folds behind an `Output` toggle; the commands stay visible. The two cannot be combined.
The slot holds code fences and nothing else; the build fails on anything more.

## Marked lines and numbered badges

A fence takes Expressive Code's line markers, and a marked line keeps its prompt and its column: `{2}` highlights line 2, `ins={2}` and `del={2}` tint it green or red.
A **labelled** marker, `{"1":2}` (label `1` on line 2), also draws the label as a small badge at the line's right edge, so the prose below can say "line 1".
Highlight to draw the eye, badge to cite a line by number. A screen reader skips both: the sentence under the session carries what every marker says, so always write that legend.

A script included with `<<<` takes the same meta after the language: `<<< @/_scripts/lock.sh{sh {"1":1} ins={2}}`.

## Events

None. The session fires no events; `play` only starts the typing loop.

## Keyboard

No APG widget pattern applies. A command's copy button is a plain button in the tab order.

- <kbd>Tab</kbd>: Next command's copy button, or the next Output toggle with `collapsed`.
- <kbd>Enter</kbd> or <kbd>Space</kbd> on an Output toggle: Open or close that output.
- <kbd>Enter</kbd> or <kbd>Space</kbd>: Copy that command.
