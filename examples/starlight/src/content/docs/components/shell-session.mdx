Fences alternate by position: the first, third and so on are commands, the second, fourth and so on are outputs.
A command with no output goes in the same fence as the next command.
The session reads like a shell: every command line starts with an accent `$`, every output line with a `>` and the whole line is in the comment colour, whatever the output's language.
The markers are drawn, not text: they are neither selected nor copied, and a `\` continuation line gets a `$` too.
A command has a copy button, which copies only the command; an output has none.
The slot holds code fences and nothing else; the build fails on anything more.

<ShellSession title="Lock and build">
```sh
ocx lock
```
```text
locked 3 tools in ocx.lock
```
</ShellSession>
