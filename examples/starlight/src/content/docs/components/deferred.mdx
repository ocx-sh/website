Some content is worth having but never worth the first round trip. Examples are a terminal session, a tabbed
code sample and a table of dependencies. `Deferred` ships only a skeleton you size to match it. The real
content lives in its own page under `frag/`, built with the `FragmentLayout`. It arrives after the
`load` event once the browser is idle, or at the first input if that comes sooner.

The fragment page is a bare document. It has no site CSS or header. It is `noindex`, outside the sitemap and the
search index. What it brings is the component's own HTML, styles and scripts. The loader fetches it,
adds its stylesheets and waits for them, inserts the body, runs its scripts and announces
`ocx:inserted`.

Every component script mounts through that event. A Tabs, a CommandBar or a
Terminal inside a fragment is therefore as live as one in the page. Then the content fades in over the skeleton
(instantly under reduced motion).

```astro
---
import Deferred from '@ocx-sh/theme/components/Deferred.astro';
import Skeleton from '@ocx-sh/theme/components/ui/Skeleton.astro';
---

<Deferred src={`${import.meta.env.BASE_URL}frag/shell-session/`} label="Shell session">
  <Skeleton slot="skeleton" variant="code" code={'ocx lock\nlocked 3 tools\n'} />
</Deferred>
```

```astro
---
// src/pages/frag/shell-session.astro: fences need MDX, so the content is a separate file.
import FragmentLayout from '@ocx-sh/theme/layouts/Fragment.astro';
import Content from '../../fragments/shell-session.mdx';
---

<FragmentLayout title="Shell session">
  <Content />
</FragmentLayout>
```

## The rules

- **Size the skeleton to the content.** The skeleton and the content share one grid cell, so the box is
  the larger of the two. A matching skeleton means nothing moves. Use a `Skeleton` composite
  (`code`, `terminal`, `table`, `card`) built from the same source as the content, or draw one and mark
  it `data-swap-skeleton`. The `skeleton` slot is required, or the build fails.
- **Defer only what a visitor can do without.** With scripting off the skeleton stays and a link to the
  fragment shows. Never defer the largest element in the first viewport, or the only copy of text a
  crawler must see.
- **A failure keeps the box.** A failed fetch, script import or stylesheet stops the sweep, the message and a Retry button show, and Retry tries again. `ocx:deferred:load {ok}` reports the outcome on the box.

## Events

- `ocx:inserted` (bubbles, from the content cell): the fragment's markup is in the page. Every component script mounts from it. Listen to enhance the fragment yourself.
- `ocx:deferred:load` `{ ok }` (bubbles, from the box): the load finished. `ok` is false on an error.

## Keyboard

| Key | Action |
|---|---|
| Enter, Space | On Retry: fetch the fragment again; focus moves to the box. |

Deferred has no other keys. The loaded content brings its own.
